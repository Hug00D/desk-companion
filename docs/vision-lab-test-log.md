# Vision Lab 測試紀錄

本文件保存 Vision Lab 每次實驗的可讀摘要。原始逐幀資料、Ground Truth、預測事件與
metrics CSV 放在專案根目錄的 `vision_lab_out/`，並由 `.gitignore` 排除；CSV 是原始證據，
本文件則是應提交到 Git 的研究紀錄。

- 驗收範圍與停止條件：[`PILOT.md`](../PILOT.md)
- 執行與比較方式：[`README.md`](../README.md#vision-lab離線視覺量測)

## 紀錄規則

1. 每批實驗新增一節，不覆寫舊結果。
2. 一律記錄日期、影片來源、run ID、Ground Truth 規則、策略參數與使用的 CSV 檔名。
3. 「逐幀指標」與「事件指標」分開記錄：
   - Precision／Recall／F1 與 frame accuracy 是逐幀指標。
   - 誤報事件、漏失事件、狀態切換與 onset delay 是事件／時序指標。
4. Precision = TP / (TP + FP)，Recall = TP / (TP + FN)，F1 是 Precision 與 Recall 的調和平均。
5. Ground Truth 沒有某狀態的真實樣本時，該狀態的 Recall 與 F1 記為 `N/A`，不得填 0
   或宣稱模型已驗證該狀態。
6. 延遲定義為 `predicted_onset - true_onset`；負值表示模型比人工標記的起點更早觸發。

## Pilot v1：單幀 vs 3-of-5

### 目的

確認使用相同的逐幀特徵時，因果 3-of-5 投票能否減少零記憶單幀分類造成的誤報與狀態抖動，
並量化它增加的偵測延遲。MediaPipe 每支影片只執行一次；兩種策略均從相同的
`frame_features_*.csv` 後處理產生。

### 策略設定

| 策略 | 設定 |
| --- | --- |
| 單幀 | 直接使用當前列 `raw_state`，無計數器、鎖定、遲滯或 cooldown |
| 3-of-5 | 只看當前列與前四列；同一狀態至少 3 票才輸出，視窗不足或無多數時輸出 `normal` |

狀態集合為 `normal`、`eye_closed`、`head_turned`、`posture_down`、`user_missing`。

### 初步觀察

> 在 3 段影片上，3-of-5 將總誤報事件從 176 次降至 72 次，閉眼誤報事件從 50 次降至
> 39 次，狀態切換從 238 次降至 124 次，漏失維持 0 次；代價是平均偵測延遲增加約
> 0.067 秒。

- 3-of-5 明顯減少事件碎裂與狀態抖動，但加權 frame accuracy 只增加 0.7 個百分點。
- test1 有 700 / 960 幀被單幀規則判為 `eye_closed`。這是持續性的單幀規則偏差，投票無法
  像處理短暫眨眼那樣消除。
- test2 的平均延遲為負值，代表預測事件比人工 Ground Truth 邊界更早開始；這可能同時受到
  粗略人工邊界與模型提早誤觸發影響，不能直接解讀成「偵測更快」。
- 本結果支持「3-of-5 可降低短暫抖動」；尚不足以宣稱整體視覺分類已達高準確率，也不足以
  評估真正閉眼事件的 Recall。

### 決策

Pilot v1 已完成，停止增加報表 UI、5-of-7、遲滯、cooldown 或批次掃描。若另開 v2，第一個
研究問題應限定為持續性 `eye_closed` 誤判，並使用新的校正影片調整規則，再用未參與調參的
影片驗證，避免在同一批資料上調參與宣稱改善。

## V2 診斷 1：test1 持續性閉眼誤判

### 日期與問題

- 日期：2026-08-31
- Branch：`codex/vision-lab-v2-eye-calibration`
- 問題：為什麼 test1 有 700 / 960 幀被零記憶規則判為 `eye_closed`？
- 本階段只讀取 Pilot v1 的原始 CSV，沒有修改 FrameClassifier 或正式 app。

### 三支影片的 EAR 概況

`Face + EAR` 是同時有臉且左右 EAR 完整的幀數；閉眼比例以這些幀為分母。

| 影片 | 總幀數 | Face + EAR | `raw_eye_closed` | 閉眼比例 | 平均 EAR 中位數 | 平均 EAR Q25–Q75 | abs(pitch) 中位數／Q95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| test | 1707 | 1205 | 318 | 26.4% | 0.1781 | 0.1451–0.2013 | 4.4° / 47.1° |
| test1 | 960 | 960 | 700 | 72.9% | 0.1577 | 0.1471–0.1640 | 2.4° / 4.8° |
| test2 | 1013 | 269 | 147 | 54.6% | 0.1621 | 0.1305–0.1746 | 2.2° / 33.1° |

test2 有大量趴下與離席區段，不能把上表的閉眼比例直接當正常坐姿誤判率；此表只用來比較
輸入特徵的尺度。

### test1 的 Ground Truth 分解

| Ground Truth | 幀數 | 判為 `raw_eye_closed` | 比例 |
| --- | ---: | ---: | ---: |
| normal | 828 | 691 | 83.5% |
| head_turned | 132 | 9 | 6.8% |

test1 全部 960 幀都有臉與左右 EAR，且 abs(pitch) 中位數僅 2.4°、Q95 僅 4.8°，因此持續
閉眼誤判不是缺臉、低頭或 reading-pitch 門檻縮放造成。左右眼 EAR 中位數分別為 0.1670 與
0.1477，存在明顯不對稱；右眼中位數已落在目前規則的低開眼區間。

目前 EAR 會先以 `[0.13, 0.27]` 映射到 `[0, 1]` 的開眼機率，再要求：

```text
min(left_open, right_open) < 0.18
且 average(left_open, right_open) < 0.28
```

在沒有 reading-pitch 縮放且 EAR 尚未被 clamp 的範圍內，這約等於單眼 EAR 小於 0.1552，
同時雙眼平均 EAR 小於 0.1692。test1 的正常坐姿分布大量落在這兩個門檻以下，所以形成
持續性錯誤；3-of-5 只會保留持續錯誤，無法像過濾單次眨眼一樣消除它。

### 結論與停止點

- 原因定位為固定 EAR 映射／門檻不適合 test1 的人物與拍攝條件，而不是 PTS、3-of-5、
  face detection 或 pitch 判斷失敗。
- Pilot v1 三支影片的 `eye_closed` Ground Truth support 為 0，沒有真正閉眼樣本可估計 Recall，
  因此現在不能根據正常幀單方面把門檻調低；那會有漏掉真正閉眼的風險。
- 在取得校正影片以前停止修改 FrameClassifier。

### 下一個最小實驗：閉眼校正影片

使用同一支 iPhone 16、相近距離與光線，固定拍攝一支約 30–45 秒影片，依序包含：

1. 0–8 秒：正常睜眼看前方，標為 `normal`。
2. 8–13 秒：自然眨眼數次，Ground Truth 仍標為 `normal`。
3. 13–18 秒：持續閉眼約 5 秒，標為 `eye_closed`。
4. 18–26 秒：低頭看書且眼睛保持睜開，依本專題的使用情境標為 `normal`。
5. 26 秒到結束：回正並正常睜眼，標為 `normal`。

這支影片只用於選擇閉眼門檻；調整完成後，必須另外錄製至少一支未參與調參的驗證影片，
再報告新的 Precision／Recall／F1，不能直接用校正影片宣稱改善。

## V2 診斷 2：個人化睜眼 EAR P90

### 假設與方法

固定的 `OPEN_EYE_EAR = 0.27` 高於四支影片多數正常睜眼量測值，因此先用既有 CSV 模擬
個人化睜眼基準，再修改 Vision Lab 程式重算一次。校正只使用每支影片前 4 秒、偵測到臉、
左右 EAR 完整且 `abs(pitch) < 15°` 的樣本；左右眼分別取 P90。每支影片都有 119 個有效
校正樣本。前 4 秒在所有 Ground Truth 中皆為 `normal`，但仍屬同批資料內校正，不視為獨立驗證。

選 P90 而不是最大值，是為了避免單一 landmark 離群值。離線推估在 test3 上的結果如下：

| 睜眼基準 | 左／右 EAR | 閉眼 Precision | 閉眼 Recall | 閉眼 F1 | Frame accuracy |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定 0.27 | 0.2700／0.2700 | 23.8% | 100.0% | 0.384 | 60.8% |
| 前 4 秒最大值 | 0.2171／0.1724 | 44.6% | 100.0% | 0.617 | 81.9% |
| 前 4 秒 P90 | 0.2118／0.1654 | 44.9% | 100.0% | 0.620 | 82.0% |

### 實作後的校正值

使用 `tool/vision_lab_reclassify.dart` 從原始逐幀特徵產生 `frame_features_p90_*.csv`；沒有
重新執行 MediaPipe，也沒有覆寫原始 CSV。同一份 test3 輸入重算兩次後以 `fc.exe /b`
比較為無差異。正式 app 的 `EyeStateDetector` 沒有修改。

| 影片 | 校正樣本 | 左眼 P90 | 右眼 P90 |
| --- | ---: | ---: | ---: |
| test | 119 | 0.248910 | 0.178425 |
| test1 | 119 | 0.195295 | 0.171274 |

### 假設與凍結規則

- 日期：2026-09-01
- Branch：`codex/vision-lab-v2-validation`

  離線重算時啟用，既有 `--mode=p90` 行為保持不變。

test3 正坐 normal 的 `abs(pitch)` P90 為 3.1°，低頭閱讀中位數為 33.3°。因此將開始補償

## V2 探索分析：移除固定閉眼端點

### 問題與資料角色

- 日期：2026-09-02
- Branch：`codex/vision-lab-v2-pose-context`
- 使用 test3、test4、test5 的既有逐幀 EAR 與 Ground Truth；MediaPipe 未重跑。
- 本節是用來提出候選規則的探索分析，三支影片都已參與選擇門檻，不能再當獨立驗證集。
- 指標只評估 `eye_closed`／非 `eye_closed` 二元任務，姿勢與離席不列入本表。

現行算法先用左右眼前 4 秒 P90 當個人睜眼基準，但另一端固定使用 `EAR = 0.13` 當完全
閉眼，再把 EAR 映射成 openness。資料顯示固定端點會丟失有用差異：test5 右眼在低頭閱讀
時 EAR 中位數約 0.098，真正閉眼約 0.055；兩者原本可分，但都低於 0.13，因此都會被截成
openness 0。

三片的 P90 約為左眼 0.206–0.217、右眼 0.165–0.173。P90 取分布高端，不會被少數眨眼
拉低；改用單一最大值反而更容易受雜訊影響，也會讓大部分幀的相對 openness 更低。

### 候選規則

移除固定 0.13 閉眼端點，保留個人 P90，直接計算：

```text
relative_ear = ((ear_l / p90_l) + (ear_r / p90_r)) / 2
closed_candidate = relative_ear < 0.50
```

`0.50` 是在 test3–test5 上探索得到的候選值，不是文獻常數，也不是已驗證的正式參數。

### 三片合併結果

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 現行 P90＋固定 0.13 端點 | 79.0% | 37.8% | 99.8% | 54.9% | 910 | 1 | 3 / 3 |
| `relative_ear < 0.50` | 97.6% | 84.4% | 99.3% | 91.2% | 102 | 4 | 3 / 3 |
| 上列＋連續 300 ms | 99.1% | 99.6% | 93.0% | 96.2% | 2 | 39 | 3 / 3 |

300 ms 的 frame Recall 較低，是因為每個事件開頭的確認期間會被計為漏失幀；三段長閉眼事件

### 結論與下一步

- 目前資料支持「固定閉眼端點 0.13 不適合這位使用者／拍攝條件」，不支持「P90 被眨眼
  污染」。
- 相對 EAR 比例比現行 openness 映射更能保留低頭閱讀與真正閉眼之間的差異。
- 300 ms 持續時間可以排除資料中的大部分眨眼／短暫遮擋，代價是約 0.3–0.4 秒延遲。
- 暫不改正式 App。先把候選規則凍結為 `relative_ear < 0.50`＋300 ms，再用全新的 test6
  驗證；test6 必須包含眨眼、瞇眼、戴眼鏡閱讀、閱讀中眨眼和持續閉眼。
- 若要精確比較 live app，CSV 還需要記錄原生端融合 blendshape 與 landmark 後的左右眼

### V2 開發：test7 動態觸發＋睡眠 latch

- 日期：2026-09-03
- 定位：test7 自本節起改為開發資料；本節數字不是獨立驗證結果
- 目的：補足固定深度規則只能在打瞌睡頭降得夠深時短暫觸發的問題，同時維持閱讀低誤報
- 原始 CSV 未修改；正式 App 未修改；候選只輸出新的後處理 CSV

test7 的順序特徵是：打瞌睡開始時，使用者先在接近正坐的位置持續閉眼，接著頭部下降；
閱讀開始時則是頭先下降，低頭後 EAR 才因眼鏡與角度出現大量 `raw_eye_closed`。因此動態路徑
不把 Pitch 速度單獨當成睡眠，而使用以下時序：

```text
baseline = 前 5 個合格 Pose 樣本的 nose_y_ratio 中位數

靜態路徑（沿用 test6，未調整）：
  nose_y_ratio - baseline >= 0.13

動態路徑（test7 開發）：
  接近正坐：nose drop <= 0.05 且 abs(pitch) <= 15°
  接近正坐時 raw_eye_closed 持續 >= 300 ms → arm
  arm 後 2 秒內 nose drop >= 0.06 且 abs(pitch) >= 15° → sleeping latch
  若 arm 後維持正坐且睜眼 >= 500 ms → 取消 arm
  latch 後，臉與頭部穩定回正 >= 2500 ms → normal
  最終 raw_state = 靜態路徑 OR 動態 latch
  再套因果 3-of-5
```

#### 候選規則

```text
depth_candidate = pose_detected 且 nose_y_ratio - baseline >= 0.13
shoulder_width = hypot(left_shoulder_x - right_shoulder_x,
                       left_shoulder_y - right_shoulder_y)
gap = ((left_shoulder_y + right_shoulder_y) / 2 - pose_nose_y) / shoulder_width

幾何可用：座標皆有限，image_height > 0，肩寬 >= 0.05 × image_height，
          鼻子／左右肩 visibility 各在 [0.5, 1] 內
static_sleeping = depth_candidate 且 幾何可用 且 gap <= 0.15
最終 sleeping = static_sleeping 或原 stable-arm 的 dynamic latch
最後再套同一因果 3-of-5
```

gap 是鼻子到雙肩平均高度的有號垂直距離，以投影肩寬正規化；負值表示鼻子已低於雙肩平均
高度。不需要看到眼睛或臀部，但「看不到臉」本身絕不是睡眠證據。這是新增的姿勢條件，
仍與原鼻子深度相關，不是獨立的閉眼或生理睡眠證據。

  ground truth CSV 重跑並經過相同的可重現性驗收。
- 建議：暫停在現有 EAR／深度／肩膀／眼部融合特徵上繼續調參找「低頭閱讀 vs 低頭
  睡覺」的規則。若要再嘗試，下一個真正沒測過的變因是相機擺放角度（頭低下時能否

## 手機 Pilot 修訂：缺資料寬限與髖部回座護欄

- 日期：2026-10-20；延續上一節尚未提交的 App Pilot 修改。本節取代上一版「缺資料立即
  重置」與「看到人後固定等 1.5 秒」；上一節的 241 項結果屬於當時版本，不能冒充本版驗證。
- 使用者確認取景前提：固定書桌鏡頭，坐著時桌子遮住髖部，站著時髖部可能進入畫面。
  髖部只作離席回座過渡護欄，不做一般坐站分類，不改平時睡眠條件。

### 趴下候選的有限寬限

- 保留快軌原有姿勢／向下動作／投票條件，手機仍須累積至少 1200 ms 的可靠新 Pose 證據。
- 缺 Pose 或動作品質不足時，候選暫停最多 1500 ms；期間不增加有效時間與投票，也不以
  不可靠座標更新姿勢濾波器。恢復可靠 Pose 且仍符合條件後，先保留原進度，再從之後的新
  正向觀測繼續累積；從缺失前最後一次觀測到恢復當次的整段間隔不算證據。
- 例：已有 600 ms，有一次缺失，恢復時仍是 600 ms，不能直接變成睡眠；之後再取得
  600 ms 有效證據才達 1200 ms。這是容忍未知資料，不是忽略所有快速動作。
- 寬限從第一次缺失開始算；反覆缺失不能重啟寬限。超過 1500 ms、超過允許的 1500 ms
  新 Pose 間隔，或出現不符合趴下的可靠姿勢，清掉候選。沒有新 Pose 也不能讓候選永久保留。
- 已確認趴下仍沿用原有缺失保持／恢復規則；本次寬限只控制尚未確認的候選，不把追蹤消失
  當作新的睡眠證據。離線預設 `minimumEvidenceDuration = 0`、寬限為 0，既有回放行為不改。

### 離席回座護欄

1. 只有最終狀態已確認 `userMissing` 才啟用；短暫丟臉不直接當離席。
2. 使用原生既有的 `poseLeftHip*`／`poseRightHip*` 欄位，補齊 Dart 座標與可見度欄位，
   不新增模型、不新增每幀推論，也不改 CSV schema。
3. 任一側髖部可見度至少 0.6、座標有限且在畫面內，就維持 `standing` 回座護欄，不能因
   人已站了幾秒便恢復趴下累積；此名稱是本取景條件下的過渡線索，不是通用站姿分類結果。
4. 髖部不再可靠可見時，仍須可靠的頭肩 Pose 接近原坐姿基準，且連續新觀測穩定至少
   1500 ms；下降中、樣本過時、完全消失、弱 Pose 都不能完成回座。Face 暫時抓不到時，
   可靠且回到基準的頭肩 Pose 仍可確認坐好，不強制眼睛或臉一直可見。
5. 已看到過髖部後，髖部欄位缺少／非有限數不能當作遮擋證據。未曾看到髖部、但已有坐姿
   基準的舊資料格式，可用頭肩位置與穩定性回復；仍不能只靠經過幾秒就解除。
6. 沒有舊坐姿基準時，須明確有髖部資料且髖部不可見、臉朝正、連續五個可靠且穩定 Pose
   才建立首個基準；缺欄位的未知資料不能用來建立它。這也依賴上述固定書桌取景前提。
7. 回座確認前不累積快軌趴下；確認時清除坐下動作與舊低頭情境，再從新 Pose 開始。
   原本已建立的坐姿校準保留，之後真正趴下仍可觸發。正常坐著期間不使用髖部擋睡眠。

正常坐姿的頭肩參考取五個有效樣本中位數。回座位置容許鼻子／肩膀中心垂直偏差為畫面高度
的 6%，水平偏差為寬度的 10%，肩寬比例偏差 30%；穩定要求相鄰觀測鼻子／肩膀垂直和
肩膀水平位移不超過各軸的 1.5%。這些與 0.6 可見度、1200／1500 ms 都是可調工程起始值，
不是經過實機校準的睡眠或坐站判斷門檻。相機位置改變後應重新校準。

### 診斷與驗證

- Debug 面板新增回座護欄階段、左右髖部可見度、有效趴下證據毫秒數與「暫停」標示。
- 針對性測試涵蓋寬限不補秒、寬限邊界與超時、可靠姿勢恢復、舊 Pose、已確認趴下保持、
  髖部解析、長時間站立、單側髖部、畫面外／非有限座標、丟失髖部欄位、坐下中、回座坐穩、
  無臉可靠 Pose、回座後再趴下與缺少初始基準。
- 本版針對性測試 39 項通過；`flutter test --no-pub test/vision test/focus test/voice` 共
  264 項通過。對本輪 7 個 Dart 檔執行 `flutter analyze --no-pub` 沒有問題；
  `git diff --check` 通過。沒有重跑真實影片／CSV 指標、建置 APK 或執行實機驗證，
  因此不宣稱實機誤觸率已降低。

### 實機檢查與限制

- 先自然坐正建立基準；離席後回來站著超過 5 秒，Debug 的護欄不應僅因時間到就解除。
- 坐下途中即使鼻子快速下降，仍不應輸出趴下；坐正穩定後才回到 `inactive`，再真正趴下
  確認仍能觸發。另測後仰靠椅背再坐正的低機率短暫誤觸。

  無法區分坐站。這版不識別人物身份，也沒有解決「其他人走到鏡頭前」的身份問題。

### 仍未解決的睡眠慢軌問題

- 9～27.9 秒讀書期間，`sleep_first_state=sleeping` 共 13.465／18.9 秒（71.2%）；主要誤報
  區間為 12.501～19.536 與 21.570～28.836 秒。這表示睡眠慢軌仍不能當作高信心睡眠
  提醒，與本次離席／趴下護欄通過是兩個不同結論。
- 此讀書區間 Face／Pose 沒有形成超過 5 秒的連續同時遺失，人體遮罩也沒有取樣；因此
  test14 驗證了另一支影片上的一般讀書與真正趴下，但不是「讀書時 tracker 長時間消失且
  人體仍在」的全新困難負例。不能據此宣稱該情境已完全泛化。

### 結論與停止點

- 保留 test13 建立的 `presence_confirmed_prone` 規則：test14 再次做到兩段離席 0 秒趴下
  誤判，且真正趴下在約 5 秒後成立。暫時不再用 test14 調整 5 秒或下墜門檻。
- 離席解除仍有 1.4～2.6 秒過渡保持，但目前只出現在回座調整階段；若要優化，應獨立處理
  回座解除，不要放寬趴下證據。
- 下一輪若繼續研究睡眠，應針對讀書期間大量 `sleeping` 的原因另開規則假設與新影片；
  不把這個問題混入已通過的離席／趴下護欄。
