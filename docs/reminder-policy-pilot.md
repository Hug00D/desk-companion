# 保守提醒實機試用

這一輪的目的不是證明使用者「真的睡著」，而是確認 App 在可能需要休息時介入，是否有用且不會造成過度打擾。

## 啟用方式

1. 開啟 App，從底部導覽進入「任務」。
2. 在「專注保護」開啟「保守提醒試用」。
3. 啟動一輪番茄鐘並回到首頁，讓相機持續看到上半身。
4. 正常讀書或工作 45–60 分鐘；不要刻意一直演出睡眠，只記錄自然發生的提醒。

此開關預設關閉，關閉時維持原本的提醒與自動暫停行為。開啟後只改變提醒決策，不修改 `CompanionStateEvaluator` 的視覺判斷。

## 試用策略

| 觀察結果 | 持續時間 | App 行為 |
| --- | ---: | --- |
| 正常／短暫注意力波動 | — | 不詢問 |
| 持續閉眼／疲勞跡象 | 3 秒 | 顯示一次中性詢問 |
| 疑似打瞌睡跡象 | 3 秒 | 顯示一次中性詢問 |
| 已確認的趴低姿勢 | 8 秒 | 顯示一次中性詢問 |
| 持續視線偏離 | 15 秒 | 顯示一次中性詢問 |
| 離席 | — | 只記錄，不對空位提醒或自動暫停 |

詢問文字使用「要繼續專注，還是先休息一下？」；App 不會在提醒中宣稱使用者已經睡著。

## 按鈕與冷卻

| 使用者操作 | 結果 |
| --- | --- |
| 繼續專注 | 同一原因冷卻 10 分鐘，且必須先恢復後才能成為新事件 |
| 休息一下 | 若番茄鐘正在執行則暫停；同一事件不再詢問 |
| 5 分鐘後提醒 | 若相同跡象仍持續，5 分鐘後可以再詢問一次 |
| 關閉／點擊外部 | 視為未回覆，冷卻 15 分鐘且等待狀態恢復 |

冷卻是依「狀態＋原因」分開計算，例如趴低與視線偏離不共用同一個冷卻。單純時間到不會讓同一個未恢復事件重新轟炸使用者，只有「5 分鐘後提醒」例外。

## 第一次實機驗收

請朋友完成一輪 45–60 分鐘的自然讀書／工作，結束後補下表。第一輪先觀察是否打擾，不用再調辨識門檻。

| 日期／測試者 | 使用時間 | 總詢問數 | 覺得有用 | 不需要／誤報 | 太早／太晚 | 備註 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 |

建議第一輪暫定驗收目標：每小時「不需要的詢問」不超過 1 次。測試者每次只需記下大約時間、當時在做什麼，以及按了哪個按鈕。

如需從 Android Studio／ADB 協助核對，搜尋 logcat 關鍵字：

```text
Focus intervention:
Reminder policy response:
```

## 自動測試

```powershell
flutter test --no-pub `
  test\focus\reminder_policy_test.dart `
  test\focus\focus_session_monitor_test.dart `
  test\focus\reminder_policy_widget_test.dart
```

`reminder_policy_test.dart` 驗證門檻、離席抑制、冷卻與重新觸發；`focus_session_monitor_test.dart` 驗證試用策略接進正式監測流程後，不會播放舊式即時提醒或自動暫停；widget test 則驗證正式 App 的開關確實能切換策略。
