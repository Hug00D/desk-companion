# 逐輪專注評分紀錄

更新：2026-11-08。依使用者選擇，先做依帳號區分的本機保存。

## 使用流程

完成一輪專注 → 自動保存完整評分表 → 統計頁「逐輪評分紀錄」 → 點選場次 → 重新查看當時的評分表。

「範圍總覽」仍是後端彙整的時長、輪數與事件；新增的逐輪紀錄是另外保存在此裝置的報告，不以總覽數字推算或補造評分。

## 保存內容

- 每輪獨立 ID、開始與完成時間。
- 計畫時長、有效專注時間與非專注時間（含離席）。新版另存離席時長，並顯示整輪未觀測時間及資料涵蓋率。
- 各狀態事件次數，以及姿勢過低／疑似瞌睡等原因次數。
- 完成時的分數、等級與評語快照。重新開啟時使用保存的評分，不因日後公式調整而重算舊分數。
- 有效觀測不足的完成場次同樣保存，列表顯示「資料不足」，保留未評分狀態。

## 保存範圍與邊界

- 帳號各自保存；訪客另外保存。切換帳號時不顯示前一個帳號的報告。
- 重開 App 後仍能讀回；列表依完成時間由新至舊排列。
- 本輪不新增後端 API、資料庫欄位或跨手機報告同步；目前後端統計流程繼續運作。
- 新版啟用後完成的場次才會自動保存。過去只有彙總資料、沒有保存完整評分表的場次，不會自動出現在歷史報告中。
- 中途停止的場次原本不會產生完成評分表，本輪也不替未完成場次生成分數。
- 清除 App 資料或解除安裝會移除本機報告；一般覆蓋更新保留 App 資料。
- 儲存採用暫存檔與替換方式，避免直接覆寫一半；同帳號寫入依序處理，相同輪次 ID 不會重複加入。
- 已有檔案無法讀取時，顯示錯誤並保留原檔，不用空列表覆蓋原紀錄。

## 驗證

- 新的 repository 實例可從檔案完整讀回報告，模擬 App 重開。
- 保留原始分數／評語與未評分狀態。
- 帳號／訪客隔離，特殊帳號字元不影響檔案路徑。
- 多筆並行保存不漏資料、排序正確、重複 ID 不新增第二筆。
- 損壞的既有檔案不會被下一次保存覆蓋。
- 紀錄列表能點開指定評分表、關閉返回，切換帳號後不顯示舊紀錄。
- 後端統計失敗時，仍可從統計頁進入本機逐輪紀錄。

## 離席仍滿分修正（評分 v2）

- 舊公式用「有效專注 ÷ 已觀測時間」計分，只取得少量正常資料、其餘時間缺少資料時，仍可能得到 100 分。
- 新公式：有效專注時間 ÷ 預定時間 × 100，再扣既有事件分數（注意偏移每次 1 分，疲勞／離席每次 2 分，合計最多扣 10 分）。分數限制於 0–100；原有最低觀測門檻保留。
- 離席屬於非專注，不重複加入觀測總時間。未觀測時間不推定成離席，也不算有效專注。
- 第一筆有效觀測前不預設正常；沒有臉／姿勢且尚未確認離席的過渡畫面不累積專注；超過 3 秒的資料空檔不延續前次狀態。
- 最近有效樣本距離結束不超過 3 秒時，補計最後一段時間；暫停期間的樣本不納入專注時長。
- 新報告保存評分版本 2；舊報告保留原分數並標註「舊版評分」，未分開保存的離席時長顯示「未分開紀錄」。
- 回歸測試：專注 20 秒＋離席 40 秒得到 31 分；全程離席為 0 分；只觀測到正常 15 秒的 1 分鐘場次為 25 分、未觀測 45 秒；完整正常 1 分鐘仍為 100 分。

## 離席與非專注均為 0 的後續修正

使用者補充原報告的離席次數、分心時間皆為 0，不能僅以評分公式問題解釋。新增完整「CompanionController → FocusSessionMonitor → FocusSessionReport」測試，在 600ms 取樣、先看見臉但沒有可靠肩膀歷史、之後持續無人的情境，且人體遮罩模型無回覆時，重現最終狀態一直為 normal，離席未進入報告。修正前測試失敗紀錄：`.codex_tmp/vision-report-before.log`。

雙軌情境判斷的 unknown 覆蓋了基礎偵測已確認的 userMissing。新版在持續全無臉／姿勢、基礎偵測已確認離席、沒有下降／低頭或睡眠鎖定情境時，保留離席結果；不再依賴人體遮罩模型一定成功。人體遮罩仍判有人時不猜測成離席，也不把缺少臉／姿勢的時間當成有效專注。

完整流程測試涵蓋人體遮罩無回覆、回覆無人、回覆有人三種情況；前兩者能保存離席次數及時長，第三者顯示未觀測時間而非滿分。既有趴下／回座測試維持通過。這是已重現並修正的程式路徑，尚無該手機原報告的原始偵測紀錄可證明現場唯一原因。

最新完整 Flutter 測試 373 項通過；`flutter analyze --no-pub lib test` 通過；Android debug APK 已建置。驗證紀錄使用 `.codex_tmp/vision-report-all-tests.log`、`.codex_tmp/vision-report-analyze.log`、`.codex_tmp/vision-report-build.log`。

上述新功能的實機完成一輪／重開後查看流程仍待驗收；後續安裝狀態見下方紀錄。

## 實機補充與診斷欄位

使用者確認來源是即時相機，趴下會扣分，離席可在 debug 面板看到。原面板同時列出 Presence、視覺事件、一般狀態統計與角色狀態，不能單憑「有看到離席」判定本輪計時已累計離席。

新增「本輪評分資料」：評分實際輸入、計時／暫停原因、本筆是否累計、樣本間隔、本輪有效專注／非專注／離席秒數與離席事件次數。原有統計改標「一般狀態累計（非本輪評分）」。離席時長應在有效觀測且計時進行時增加，離席事件需有效離席觀測累積滿 5 秒；超過 3 秒的樣本空檔不延續前次狀態。

相應測試確認暫停、無效觀測及過長資料間隔可辨認為本筆未累計；相關 54 項測試、靜態分析及 APK 建置通過。未另外改動趴下閾值或評分規則。手機本次沒有可讀取的 App 視覺診斷，尚未取得原場次的實際漏記原因。新版已用 `adb install -r` 覆蓋更新至 Pixel（4B051FDAS002RY），回覆 Success，保留 App 資料；未替使用者啟動計時或操作其他 App。已請使用者在一分鐘體驗倒數中離席約 15 秒，核對新增的本輪離席秒數，實機結果待回覆。紀錄：`.codex_tmp/report-debug-tests.log`、`.codex_tmp/report-debug-analyze.log`、`.codex_tmp/report-debug-build.log`。

實機驗收更新：使用者依上述流程測試後回報「有了有扣分了」，確認新版在該 Pixel 的實際離席情境會影響本輪分數。本次未取得確切分數、離席秒數或原始偵測紀錄，不補造數值，也不將此結果延伸為歷史報告重開讀取或後端同步已驗收。
