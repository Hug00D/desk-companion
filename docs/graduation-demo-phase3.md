# 展示第三階段實作與驗收

更新日期：2026-11-08。範圍依本次對話確認的第三階段：08 連線與同步回饋、09 統計同步驗證、10 名稱／狀態／文案、11 資料處理說明。

後續新增需求：依使用者選擇，追加本機逐輪評分表保存與查閱，詳見 [逐輪專注評分紀錄](focus-report-history.md)。這是第三階段原範圍之外追加的紀錄功能。

## 實作內容

### 08：連線與同步回饋

- 依使用者後續調整，移除主畫面、工具選單的同步入口及紀錄／統計頁的專用同步按鈕。只有同步失敗時，才在紀錄／統計頁顯示非阻斷提示；正常同步不顯示狀態卡片。
- 系統繼續自動同步。定時同步也會重試待傳輪次；進入或重新整理統計頁時也會重試，恢復成功後失敗提示消失。
- 進入統計時直接導航，在頁面內同步、顯示進度並載入統計；不再於主畫面無回饋地等待上傳。
- 失敗的輪次建立／更新會留在記憶體待傳清單。即使開始或完成時離線、建立請求尚未完成時又結束計時，重試仍保留正確的最後狀態。
- 重試沿用 clientRoundId；伺服器已建立的輪次沿用 serverRoundId，避免同一輪重複建立。
- 重試會處理多批待傳事件，且只在收到完整的保存／重複確認後移除本機事件。
- 同步介面精簡後的相關 10 項測試通過，涵蓋定時自動重試失敗輪次、失敗提示僅於統計頁出現、恢復後消失且沒有專用同步／重試按鈕；修改檔案靜態分析通過。本輪介面精簡尚未覆蓋安裝到手機。
- 並行的上傳共用進行中的請求；session 更新依序送出。帳號改變時不會將上一個帳號的待傳資料送給新帳號。
- AI 處理及語音準備狀態顯示於主畫面的對話泡泡；語音不可播放時保留文字答案並提示。
- 目前後端將 AI 回覆與語音合成合併回傳，等待訊息會如實顯示「整理回答與準備語音」，前端沒有獨立的後端 TTS 進度事件。

### 09：統計同步驗證

已增加自動測試，驗證：

1. 輪次完成、專注時長及事件，經 FocusApi 上傳後可以由 StatisticsApi 讀回。
2. 最後一筆 completed 更新失敗後仍保留輪次，恢復後更新成功，沒有多建立一輪。
3. 離線期間完成的輪次可於恢復連線後補傳。
4. 建立輪次回覆較慢時，完成狀態不被舊的 active 狀態覆蓋。
5. 多批事件重試，以及回覆未完整確認保存時保留資料。
6. 重複點擊同步時避免重複上傳；不同帳號之間隔離待傳資料。
7. 統計頁先顯示服務失敗，恢復後重新整理能呈現資料。

上述使用測試用記憶體 HTTP 後端，不代表展示伺服器資料庫或手機相機流程已驗收。

實測環境確認：預設後端健康檢查可連線；已偵測到安裝 App 的 Pixel 9 Pro XL。使用者確認採用預設後端及手機測試帳號。

另外修正統計頁原有的版面問題：數值卡片在可捲動頁面使用 Spacer，會在成功載入資料後因高度未受限而發生排版錯誤。改為固定間隔，並加入成功載入的元件測試。

### 10：名稱、狀態與文案

- AuthSession 共用已確認的暱稱；登入進入主畫面時讀取個人檔案，讀取及儲存成功後同步更新主畫面、設定頁與個人檔案。
- 讀取較慢的舊帳號回覆不會覆蓋新帳號名稱；儲存失敗時不會將尚未保存的暱稱當成成功。
- 簡化的 sleeping 狀態會依原因顯示「姿勢過低」或「疑似瞌睡」，統計頁及任務頁也使用相同用語。
- 登入／註冊主要文字改為繁體中文；語音操作區改稱「語音與文字互動」。
- 連線錯誤使用可操作的提示，避免直接將原始例外或服務 IP 放進一般操作訊息。

### 11：資料與隱私

- 設定頁增加可開啟及返回的「資料與隱私」頁面。
- 說明相機及測試影片、裝置語音辨識、AI／語音服務、事件紀錄、本機偏好與伺服器資料的使用範圍。
- 明確說明語音事件可能包含辨識文字，安靜模式仍會記錄，以及關閉語音回覆不等於關閉監聽。
- 未同步的專注資料仍只存在本次執行的記憶體，關閉 App 可能遺失；本次沒有加入可持久化 outbox、歷史查詢或資料刪除中心。

## 登入錯誤提示修正（2026-11-08）

實機回報登入時出現「目前帳號無法存取資料，請重新登入後再試」。第三階段誤將登入頁的 ApiException 交給通用 userFacingError，會把所有 401／403 的實際原因遮蔽成上述提示。

已將登入／註冊改為專用錯誤處理：依 INVALID_CREDENTIALS、ACCOUNT_SUSPENDED、ACCOUNT_DELETED 等代碼顯示原因，未知認證拒絕保留後端訊息。原有登入 API 路徑、帳密 payload、後端驗證與預設 API 位址未修改。

新增登入成功契約、認證錯誤映射與失敗後再次送出測試，相關 6 項測試通過，修改檔案靜態分析通過。加入僅含操作、HTTP 狀態、錯誤代碼與服務位址的診斷，不記錄帳密。

目前已確認錯誤提示的回歸原因；尚未取得該使用者本次登入的實際後端錯誤代碼，不將錯誤文案修正宣稱為帳號已成功登入。

修正版 APK 已建置並覆蓋安裝。使用者回報「已成功登入」；隨後 ADB 讀到連接的 Pixel 仍停在空白登入頁，且目前程序沒有認證失敗或當機紀錄，因此正確認是否為同一支裝置。登入成功的使用者回報與尚未完成的統計實機驗收分開記錄。

後續確認：使用者停在同一支 Pixel 的登入後主畫面，ADB 已直接確認角色畫面與統計頁；上方已更新一分鐘體驗及實際統計結果。手機隨後切換至其他 App，因此停止裝置操作。尚未進行重複刷新、修改真實帳號暱稱、服務斷線恢復等額外實機測試；相關自動測試已有涵蓋。

## 後續：逐輪紀錄與離席評分

依使用者決定，新增依帳號隔離的本機逐輪評分紀錄；同步操作入口移除，僅在統計頁同步失敗時提示。細節見 [逐輪專注評分紀錄](focus-report-history.md)。

使用者回報離席仍出現 100 分後，確認舊評分只以已觀測時間為分母，沒有把整輪缺少觀測的時間反映在分數。新版改以預定時間計算有效專注比例，另列離席／未觀測時間與涵蓋率，並避免第一筆觀測前預設正常。舊歷史分數保留並標註舊版；未將此邏輯修正宣稱為實機離席偵測已通過。完整自動測試 370 項通過，實機仍待覆蓋更新及離席場景驗收。

使用者進一步確認報告中的離席與分心皆為 0。完整偵測到報告測試另重現「缺少可靠肩膀歷史且人體遮罩無回覆時，unknown 情境覆蓋已確認離席而回到 normal」。已修正此路徑並保留趴下、短暫遮擋與人體遮罩顯示有人的保護；最新完整測試 373 項通過。該次手機報告仍缺原始偵測紀錄，未宣稱已證實其現場唯一原因。

後續修正版已覆蓋安裝到同一支 Pixel，加入本輪評分診斷欄位。使用者在一分鐘體驗中測試離席後回覆「有了有扣分了」，確認離席會反映於實機本輪分數；沒有取得具體分數與秒數，不推定額外數值。逐輪歷史重開讀取與額外同步測試仍依各自驗收狀態處理。
