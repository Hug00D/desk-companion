# 畢業專題展示：介面與功能盤點

盤點日期：2026-11-03（Asia/Taipei）

## 範圍與判斷方式

以「近期截止、暫不上架、展示以主畫面為主」安排優先順序。檢查 Flutter 畫面、按鈕回呼、導航、狀態、API 呼叫及既有測試；沒有修改 App 行為。

本次沒有連接的 Android 裝置，因此屬於原始碼流程盤點，沒有實機逐鍵操作或視覺排版驗收。下文「已有實作」代表程式中有實際邏輯，不代表現場設備與服務已驗證可用。

- P0：展示前必須處理或驗收；未完成入口可先移除，不必全部補做。
- P1：基本流程穩定後，值得補完的體驗。
- P2：截止前可延後；若留在展示介面上，必須明確標示未開放。

## 核心建議

先完成一條可重複操作的展示流程：進入主畫面 → 確認相機來源與校正 → 啟動短番茄鐘 → 展示偵測、角色與提醒 → 展示語音操作 → 完成一輪 → 查看報告；若要展示統計，再確認資料確實同步到後端。

目前已具備番茄鐘、視覺狀態、角色反應、主動提醒、語音辨識與 AI 呼叫、本輪報告及統計 API 串接。優先工作應是讓這些功能容易操作、清楚呈現並可復原。

### 05．固定提醒政策，讓安靜模式與自動暫停獨立：程式實作完成，待實機驗收

- 安靜模式只抑制主動語音提醒、主動閒聊、提醒詢問、暫停建議與恢復詢問；使用者主動發起的語音互動維持可用。
- 視覺辨識、狀態時間與事件紀錄不受安靜模式影響，仍會進入本輪報告及既有同步流程。
- 修正安靜模式會略過 `autoPause` 的衝突：是否自動暫停現在只依任務頁的保守提醒政策、嚴重狀況與長時間分心開關決定。
- 若開啟安靜模式時已有提醒詢問顯示中，會關閉該詢問並停止待播提醒；不會因此改動任務頁的自動暫停開關。
- 主畫面、設定頁與任務頁補上相同邊界說明，避免把安靜模式誤解為停用偵測或停用所有專注政策。

## 實機展示驗收清單

- 冷啟動：用交付 APK 進入主畫面，角色、相機及校正正常，狀態清楚。
- 拒絕相機／麥克風權限：有清楚提示與可再次操作的路徑，影片備援有標示。
- 自訂 1 分鐘開始：回到主畫面能看見倒數；可暫停、繼續與結束。
- 偵測情境：自然閱讀、短暫轉頭、長時間分心、姿勢過低、離席與返回；確認文案與提醒符合實際情境。
- 語音：能辨識、能取消、能再說第二句；辨識失敗可改用文字；AI／TTS 暫時不可用時仍可繼續操作。
- 切頁：主畫面 → 任務／設定／統計 → 主畫面，手動暫停不被意外恢復，角色與相機能恢復。
- 背景與前景：鎖螢幕或切 App 後回來，沒有重複播放、重複啟動或計時異常。
- 完成一輪：報告能關閉、重開，能開始第二輪；若展示統計，確認後端已有同輪資料。
- 網路中斷：已登入後仍能操作本機核心流程；不能同步或 AI 回覆時有明確回饋，恢復連線後可以重試。
- 展示重置：能快速回到待機或重新開始，不必重裝 App。
